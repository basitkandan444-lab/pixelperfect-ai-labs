# SECTION 2 — WAVE A: INTERACTION SOPHISTICATION FOUNDATION

**MISSION:** Transform the approved Obsidian Precision™ system into a coherent interaction and motion system where movement improves clarity, feedback, depth, and perceived quality. This wave establishes the foundation and signature interaction patterns for later waves. Do not modify the enhancement engine, image-processing logic, ONNX/GFPGAN/WebGPU/WASM inference, Paddle backend, Supabase billing logic, authentication, or unrelated infrastructure.  
**TEAM:** JOHN — orchestration and sequencing; ELLIE — interaction art direction; SMITH — frontend motion architecture; MAYA — UX behavior and interaction states; NOVA — motion physics and choreography; ATLAS — touch, responsive behavior, accessibility and reduced motion; ELON — performance and regression QA; ALEX — independent interaction-quality review. Focused subtasks may be delegated when useful, but every reported action must actually occur.  
**MASTER LOOP:** For every interaction target use `INSPECT → MAP → DESIGN → IMPLEMENT → RUN → VERIFY → REVIEW → FIX → RE-VERIFY → ACCEPT`. Never mark an interaction complete because its animation exists. If it fails usability, accessibility, responsiveness, performance or visual quality, return it to the repair loop before continuing.  
**INTERACTION MAP:** Audit and classify the current behavior of navigation, CTAs, buttons, hero visual, upload flow, processing state, CompareSlider, image preview, download feedback, pricing, upgrade interactions, dialogs and page scrolling. For each target document the trigger, current response, intended response, motion type, user benefit, device behavior and acceptance criteria.  
**MOTION SYSTEM:** Extend the existing Obsidian Precision™ motion foundation with semantic duration, easing, spring, reveal, depth, drag and transition behaviors. Prefer transform/opacity-based animation and controlled spring physics. Do not create a separate motion system or duplicate timing values. Do not add motion merely for decoration.  
**CTA AND BUTTON INTERACTIONS:** Introduce restrained magnetic/proximity behavior only where it improves focus, with graceful fallback when pointer features are unavailable. Add tactile press/hover/focus states that remain accessible and do not interfere with clicking. Any optional haptic feedback must degrade gracefully on unsupported devices and must never be required for usability.  
**HERO DEPTH:** Evolve the existing HeroVisual interaction with subtle pointer-aware depth, layered parallax and controlled tilt. Use device-appropriate behavior, reduce or disable pointer-heavy effects on touch devices, and ensure the content remains fully understandable without motion.  
**UPLOAD TRANSITION:** Create a polished idle → selected → analysis transition that makes the image feel like it enters the product workspace naturally. The animation must not delay usability or fabricate processing activity. Verify drag/drop, keyboard selection, touch selection and error states.  
**PROCESSING CHOREOGRAPHY:** Refine the visual presentation of existing processing states so transitions between stages feel continuous and purposeful. Do not invent false progress or unsupported model claims. The UI must reflect actual application state.  
**COMPARESLIDER:** Upgrade the interaction with smooth drag response, controlled friction/spring settling and precise handle feedback. Maintain mouse, touch and keyboard accessibility. Ensure the interaction remains stable at different image sizes and viewport widths.  
**SCROLL MOTION:** Introduce restrained scroll choreography and parallax only where it improves storytelling. Avoid animating every section independently. Ensure scrolling remains natural, predictable and efficient.  
**RESPONSIVE / TOUCH:** Every interaction must have an intentional desktop and touch behavior. Pointer-only effects must have an appropriate touch equivalent or gracefully disappear. Verify interaction behavior at representative mobile, tablet and desktop widths.  
**ACCESSIBILITY:** Support keyboard interaction, visible focus, contrast, touch targets and `prefers-reduced-motion`. Reduced-motion mode must preserve meaning and feedback while removing nonessential movement. Motion must never be necessary to understand or operate the product.  
**PERFORMANCE:** Do not use “60fps everywhere” as an absolute requirement. Instead, maintain smooth interaction without visible jank and verify actual performance on representative mobile and desktop devices. Avoid unnecessary layout-triggering animation, excessive blur, huge repaint regions, uncontrolled 3D transforms and simultaneous heavy effects. Reduce effects for constrained devices when necessary. Record real findings only.  
**PRESERVATION LOCK:** Do not modify the enhancement engine or any processing logic. If a motion requirement appears to depend on a frozen system, document the dependency and defer the change.  
**EVIDENCE:** Produce representative before/after evidence for at least navigation/CTA, HeroVisual, upload transition, processing state, CompareSlider and one mobile interaction. Evidence must show actual product improvement, not just source-code changes.  
**ELON VERIFICATION:** Run the configured typecheck, build and lint checks; inspect console/runtime errors; verify responsive behavior; test keyboard, touch and reduced motion; inspect layout stability and interaction smoothness; verify no critical regressions. Report actual results and any limitations.  
**ALEX REVIEW:** Independently review timing, restraint, physicality, hierarchy, responsiveness, accessibility, performance and originality. Alex must return `REJECTED`, `ITERATING`, or `ACCEPTED` with concrete reasons. A generic statement such as “looks premium” is insufficient.  
**ACCEPTANCE GATE:** Wave A passes only when the core interaction architecture is reusable, the targeted interactions feel coherent, desktop and touch behavior is verified, accessibility works, performance remains acceptable, no critical regression exists, evidence is available, the enhancement engine remains untouched, and Alex independently accepts the result. If any criterion fails, fix it, re-test it and review again.  
**REPORTING:** After every meaningful milestone report `ACTIVE TEAM → TARGET → DISCOVERED → CHANGED → USER IMPACT → VERIFIED → BLOCKERS → DECISION → NEXT`. Do not fabricate agent activity, measurements, screenshots or approvals.  
**FINAL RULE:** Wave A establishes the interaction language; it does not attempt to animate the entire website. Build a small number of excellent, reusable interaction patterns first, then use those patterns consistently throughout later Section 2 waves.
